# LLM-Based Report Generation Module

This module provides Large Language Model (LLM) based report generation for cognitive remediation sessions, offering a dynamic alternative to template-based approaches using models like GPT-4.

## Overview

The LLM-based approach leverages structured variables extracted from session data to generate comprehensive clinical reports. This method provides:

- **Flexibility**: Adaptive report generation based on session content
- **Natural Language**: More fluid and contextual report narratives  
- **Scalability**: Easy adaptation to new domains and report formats
- **Consistency**: Reliable output structure while maintaining natural variation

## Repository Structure
```
MRG_LLMs/
├── prompts/                    # Prompt templates for different LLM approaches
│   ├── JSON_variables.txt      # Primary prompt using structured JSON variables
│   └── guideline.txt          # Alternative prompt using raw transcripts/logs
├── results/                   # Generated report outputs organized by method
│   ├── current/               # Latest generated reports (JSON, MD, HTML)
│   └── archive_results_thesis/ # Historical reports from thesis evaluation
├── archive_json_variables/    # INPUT: Structured session variables (M01E-M09E)
│   ├── M01E_seance1_0405.json # Session variables from main pipeline
│   ├── M02E_seance1_0605.json # Contains: emotions, exercises, linguistics
│   └── ... (M01E-M09E evaluation data)
├── main.py                   # Primary report generation script
└── preprocess.py             # Data preprocessing utilities
```

## Data Flow

### Input Data (`archive_json_variables/`)
This directory contains **structured session variables** in JSON format, generated by the main pipeline:

- **File pattern**: `{participant}_seance{session}_{date}.json`
- **Content**: Processed session data including:
  - Session metadata (date, duration, exercises completed)
  - Performance metrics (success rates, failed exercises)  
  - Emotion analysis results (salient emotions vs. baseline)
  - Linguistic indicators (vocabulary, speech patterns)
  - Exercise results (cognitive functions, accuracy scores)

**Example**: `M01E_seance1_0405.json` contains variables for participant M01E, session 1, recorded on 04/05.

### Output Data (`results/`)
- **Current results** (`current/`): Generated JSON responses, MD and HTML reports
- **Archived reports** (`archive_results_thesis/`): Historical reports from thesis evaluation

## Prerequisites

1. **Environment Setup**: Ensure the main conda environment is activated:
   ```bash
   # If not already done, create and activate the environment
   conda env create -f ../environment.yml
   conda activate Remediation-Sessions-Summarization
   ```

2. **OpenAI API Configuration**: Set up your OpenAI API key using one of these methods:
   ```bash
   # Option 1: Environment variable (recommended)
   export OPENAI_API_KEY="your-api-key-here"
   
   # Option 2: Add to your shell profile (.bashrc, .zshrc, etc.)
   echo 'export OPENAI_API_KEY="your-api-key-here"' >> ~/.bashrc
   source ~/.bashrc
   ```

3. **Data Requirements**: Input JSON files should be in `archive_results_thesis/` directory. These contain structured session variables from the main pipeline.

4. **Validation**: Run the setup test to ensure everything is configured:
   ```bash
   python test_setup.py
   ```

## Usage

### Basic Report Generation

**Generate a report for an existing participant:**
```bash
# Using default model (GPT-3.5)
python main.py --code M01E --seance 1

# Using GPT-4 for higher quality
python main.py --code M01E --seance 1 --model gpt-4-0613

# Specify custom output location  
python main.py --code M01E --seance 1 --save_fp results/current/my_report.json

# Full example with all parameters
python main.py \
  --code M01E \
  --seance 1 \
  --model gpt-4-0613 \
  --prompt_fp prompts/JSON_variables.txt \
  --save_fp results/current/M01E_session1_gpt4.json \
  --key your-openai-api-key
```

**Available participants in archive_results_thesis/:**
- M01E through M09E (session 1 data available)
- File pattern: `{participant}_seance{session}_{date}.json`

### Command Line Arguments
- `--code`: Participant identifier (e.g., M01E, M02E)
- `--seance`: Session number (default: 1) 
- `--model`: OpenAI model (default: gpt-3.5-turbo-0613)
- `--prompt_fp`: Prompt template file (default: prompts/JSON_variables.txt)
- `--save_fp`: Output JSON file path
- `--key`: OpenAI API key (can also use environment variable)

### Main Scripts
- `python ./main.py`: Generate reports using OpenAI models
  - Requires API key configuration
  - Supports different models and prompt types
- `preprocess.py`: Contains preprocessing functions used by `main.py`

## Generating Reports

### Using Existing Archive Data
The module comes with pre-processed session data for evaluation (M01E-M09E):

```bash
# Generate report for existing participant data
python main.py --code M01E --seance 1 --model gpt-4-0613

# With custom prompt and API key
python main.py \
  --code M01E \
  --seance 1 \
  --model gpt-4-0613 \
  --prompt_fp prompts/JSON_variables.txt \
  --save_fp results/current/M01E_evaluation.json \
  --key your-openai-api-key

# This will:
# 1. Load variables from: archive_results_thesis/M01E_seance1_0405.json  
# 2. Generate JSON response: results/current/variables_4_M01E_1.json
# 3. Create MD report: results/archive_JSON_variables/gpt-4-0613_M01E_seance1.md
# 4. Create HTML report: results/archive_JSON_variables/gpt-4-0613_M01E_seance1.html
```

### Using New Session Data
To generate reports for new sessions, first run the main pipeline:

```bash
# 1. Generate structured variables using main pipeline
cd ../generate
python main_phrases_trous.py "code:M10E;seance:1"

# 2. Copy the generated JSON to MRG_LLMs/archive_results_thesis/
# 3. Then generate LLM report
cd ../MRG_LLMs  
python main.py \
  --code M10E \
  --seance 1 \
  --model gpt-4-0613 \
  --prompt_fp prompts/JSON_variables.txt \
  --save_fp results/current/M10E_session1.json \
  --key your-openai-api-key
```
